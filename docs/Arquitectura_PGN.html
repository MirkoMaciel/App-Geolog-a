Patagonia Ground Note (PGN)

Resumen de la arquitectura y de cómo está armada la aplicación · Versión 1.2

App Android para describir suelos en salidas de campo (UNPSJB, Comodoro Rivadavia)

KotlinJetpack ComposeMaterial 3MVVMOffline-firstosmdroid / Mapsforge

1. Idea general

La app es nativa de Android, escrita en Kotlin y con la interfaz hecha en Jetpack Compose (interfaz declarativa). Está organizada en capas: la pantalla solo muestra datos y avisa lo que hace el usuario; la lógica y el guardado están separados. Todo funciona sin internet y los datos quedan en el teléfono.

Interfaz (UI)Pantallas y componentes de Compose: inicio, salidas, paradas, horizontes, exportaciones, mapa.
▲ estado (StateFlow)   |   ▼ acciones del usuario
ViewModelRecorridosViewModel: recibe las acciones, llama al repositorio y expone los datos a las pantallas. Sobrevive a la rotación de pantalla.
▼
Datos (Repositorio)RecorridoRepository: única fuente de verdad. Guarda las salidas en un archivo JSON.
▼
Servicios / archivosFotos, PDF, exportaciones, GPS y mapa: clases separadas que la UI y el ViewModel usan cuando las necesitan.

3. Técnicas y conceptos de desarrollo mobile aplicados

Arquitectura MVVM (Model – View – ViewModel)

Patrón recomendado por Google. El Modelo son los datos (Modelos.kt + repositorio), la Vista son las pantallas de Compose y el ViewModel hace de intermediario. La pantalla no guarda datos ni conoce archivos: solo dibuja lo que recibe.

Flujo de datos unidireccional (UDF)

Los datos bajan (repositorio → ViewModel → pantalla) y los eventos suben (el usuario toca → la pantalla avisa → el ViewModel actúa). Así, cada dato tiene un solo dueño y no hay copias desincronizadas.

Interfaz declarativa con Jetpack Compose

En vez de layouts XML, la interfaz se describe con funciones @Composable. Cuando cambia el estado, Compose recompone solo lo necesario. Se usa remember / rememberSaveable para el estado local (por ejemplo, un desplegable abierto) y componentes reutilizables (campos, secciones desplegables, selector Munsell, triángulo textural).

Programación reactiva con StateFlow y corrutinas

El repositorio expone las salidas en un StateFlow: cualquier cambio se refleja automáticamente en todas las pantallas. Las tareas pesadas (guardar, generar PDF, copiar el mapa) corren con corrutinas en Dispatchers.IO, fuera del hilo principal, para que la app no se congele.

Single Activity + Navigation Compose

Hay una sola Activity; las pantallas son destinos de navegación. Las rutas son clases tipadas (RutaParada(recorridoId, paradaId)), así los parámetros se controlan al compilar. Barra inferior con tres pestañas: Inicio, Salidas y Exportaciones.

Offline-first (primero sin conexión)

  • Los datos se guardan en el teléfono como JSON (kotlinx.serialization), con escritura atómica (archivo temporal + renombrar) para no corromperlos si la app se cierra a mitad.
  • Migración de datos: @JsonNames y valores por defecto permiten abrir datos de versiones anteriores.
  • Mapa sin conexión: archivo vectorial Mapsforge incluido en la app; se detecta la conectividad con ConnectivityManager y se cambia de mapa automáticamente.
  • GPS, fotos y PDF funcionan sin internet.

Recursos del dispositivo y permisos

  • Permisos en tiempo de ejecución para la ubicación (se piden solo cuando se necesitan).
  • Cámara y galería con los contratos de Activity Result; las fotos se reducen y se corrige su orientación (EXIF) para ahorrar memoria.
  • FileProvider para compartir los PDF de forma segura con otras apps (mail, WhatsApp, Drive).
  • Ciclo de vida: el mapa se pausa y libera recursos con la pantalla (LifecycleEventObserver).

Interoperabilidad Compose ↔ Views

El mapa (osmdroid) es una View clásica de Android; se integra en Compose con AndroidView. El PDF se dibuja con Canvas de Android, y reutiliza los mismos dibujos de la app (formas de concentración).

Material Design 3 y tema propio

Paleta propia "Cartografía y Estratos" (pizarra, óxido de hierro, olivino, caliza), con modo claro y oscuro, e ícono adaptable de Android.

Pruebas automáticas

Unitarias (JUnit) para la lógica pura: colores Munsell, triángulo textural, repositorio y exportaciones. Instrumentadas (en el emulador) para lo que depende de Android: generación de PDF, una salida de campo completa de punta a punta y el mapa sin conexión.
